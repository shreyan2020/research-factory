# Quality and recovery

Apply the checks that match the requested claim and artifact. Do not turn this table into mandatory ceremony for every edit.

| Dimension | Evidence that answers it | Common misleading substitute |
|---|---|---|
| Source integrity | Original/source snapshot, version, resolved locator | File exists |
| Extraction fidelity | Text/table/claim compared with original | Parser returned no errors |
| Semantic support | Correct actor, scope, direction, time, role, and relation in source context | Exact quote or valid JSON |
| Empirical benefit | Matched baseline, fixed protocol, exposure record, relevant metrics | More elaborate method or a development win |
| Cluster validity | Coverage, stability, geometry, source confounds, reviewed semantics | Attractive two-dimensional map |
| Reproducibility | Saved inputs/config, code revision, raw outputs, receipts, replay where appropriate | A report says the run finished |
| Manuscript integrity | Supported claims, citation passages, consistent corpus/methods/results | Successful compilation |
| Presentation quality | Actual rendered slides, readable hierarchy, correct evidence and sequence | Successful package validation |
| Delivery readiness | Requested file/version, editability, working interaction in relevant context | Preview link or saved placeholder |

## Failure response

**Extraction defect:** return to the source and fix the earliest transformation that lost information. Version the correction and invalidate affected derived artifacts. Preserve unchanged valid caches.

**Wrong semantic relationship:** inspect source role, actor, unit, scope, and missing context. Fix these before adding more unconstrained model calls. Do not replace a source-supported ambiguity with a decisive label for visual neatness.

**Numerical gain without practical gain:** audit changed cases and contribution of formatting, abstention, retrieval, and compute. Keep the gain's actual meaning. Do not promote it as a novel method unless the relevant claim survives matched controls and prior-art review.

**Repeated failed method:** write the shared premise, what evidence contradicts it, and the next small test that could distinguish explanations. A null result can justify retaining the baseline or abandoning the branch.

**Failed clustering gate:** preserve raw scores and the reason for any override, report eligible and excluded coverage, inspect representation failures and source confounds. Do not rename unstable groups as validated themes or silently tune against the evaluation set.

**Broken presentation integration:** distinguish artifact repair from authentication/account availability. Test a bounded route and provide the nearest usable fallback. Preserve the requested output format unless the user changes it; an alternate preview is not an exported file.

**Missing access or independent reviewers:** finish the protocol, source packets, review instrument, or local artifacts that do not depend on the missing resource. Report the specific dependency. Do not move restricted research to a different machine or fabricate completed review.

## Review effort

For a local text correction, inspect the relevant source and output. For a new high-impact research result, add an independent source/method review when feasible. For a large deck or manuscript, review the whole rendered artifact and inspect changed pages again after edits. After relevant checks pass, avoid repetitive testing unless a new change or concern warrants it.
