# Iterative presentation authoring

## Recover decisions before editing

Read the relevant user turns and inspect the latest saved artifact. Summaries help locate evidence, but assistant summaries are not the user's acceptance. When learning a preference, retain the user's correction, the artifact or slide it addressed, and its scope in local working notes. Distinguish a durable preference from a one-off content, image, or color choice.

Use the newest user-edited file, not an earlier generated export or cloud copy merely because it is easier to access. Preserve deliberate deletions, wording, sequencing, notes, and animations. Ask about the file only if current evidence leaves genuine ambiguity. Do not search cloud storage after the user has identified the local source.

## Repair the argument before decorating

State the point each slide establishes and why the next slide follows. Remove repeated prerequisites the audience already learned. Group related decisions and make the transition explicit in the spoken narrative. A collection of individually valid examples is not a coherent lesson.

Prefer one recurring example when it supports the progression. If switching cases, establish the actors, task, conditions, and relevant outcome before asking a question. For teaching a selection effect, for example, explain who is recruited, what they do, and how completion is determined before drawing the causal graph. Do not drop a diagram or “AI versus no AI” comparison into the deck without the study setup.

## Scenario → question → discussion → reveal

Show a recognizable situation before asking for a judgment. Give the audience enough information to answer; simplify or teach missing concepts first. Use their response to introduce the explanation, then connect it to the next practical decision.

For oral classroom discussion, display the question itself. Keep “ask the class”, polling mechanics, expected answers, and facilitation alternatives in notes. Do not prescribe written assignments or mandatory polling apps when the user chose oral participation. When an integration is abandoned, remove its QR codes, join codes, instructions, and residual references throughout the deck and notes.

When requested, implement click-triggered reveals in the actual file: question first, details or candidate responses next, teaching point after discussion. Group related objects so one concept appears together. Avoid automatic timed reveals that spoil the answer. Reordering or restyling must preserve the user's existing animation behavior. Static render checks cannot establish that click order works.

## Work in focused passes

1. Recover the current version and decisions; identify only the slides that need change.
2. Fix sequence, missing setup, and redundant material.
3. Select or adapt figures, realistic screens, diagrams, and purposeful humor.
4. Separate visible questions from notes and add requested reveal behavior.
5. Inspect the saved result, including layout variation, projection contrast, and the reveal states.

Before delivery, compare against the user's latest edits. Check for resurrected disclaimers, rejected images, obsolete polling instructions, lost jokes, and erased animations. Verify that new slides fit the allotted time; distinguish optional backup cases from the core lesson. Do not describe a proposed interaction or a static preview as a tested live presentation.
